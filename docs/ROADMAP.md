# PixSift — what to fix, and what to build

A working list of **features**, plus every rough edge currently in the code.

Your graded core (pHash + Hamming + k-means, per `PixSift-Project-Tracker.md`)
isn't in here — nothing below competes with it. This is the product around it.

**Legend:** `[ ]` todo · **S** ≈ a few hours · **M** ≈ 1–3 days · **L** ≈ a week+

> **One standing caveat.** Everything is still in JavaScript arrays
> (`lib/pins.ts`, `lib/comments.ts`) and **dies on server restart** —
> `MONGODB_CONNECT_URL` is in `.env` and never imported. Anything below marked
> 🗄️ needs a schema, so building it before MongoDB means building it twice.
> Everything else is safe to do now.

# Part 1 — What's broken or half-done

Real defects in the code today, not hypotheticals. Roughly worst first.

## 1.1 Wrong or missing

- [ ] **Every browser tab says "Create Next App"** — **S**
      `app/layout.tsx` still has the scaffold metadata:
      `title: "Create Next App"`, `description: "Generated by create next app"`.
      It's on every page, in every screenshot, and in every link preview you
      share. Individual pages set their own titles; the root never got fixed
- [ ] **Cloudinary is still misconfigured** — **S**
      `CLOUDINARY_CLOUD_NAME=root` fails `api.ping()` with `cloud_name
      mismatch`. Zero images uploaded. Run `bun run cloudinary:check`, fix the
      value, then `bun run seed`. Until then the whole upload path is untested
      against a real account
- [ ] **The API docs are stale** — **S**
      `lib/openapi.ts` documents `/api/health`, `/api/hello/{name}`,
      `/api/pins`, `/api/auth/session`. It's missing `/api/favorites`,
      `/api/pins/{id}/comments`, `/api/pins/{id}/comments/stream`, and
      `/api/pins/{id}/download`. `/docs` therefore lies about the API
- [ ] **`/api/hello/[name]` is tutorial scaffolding** — **S**
      Delete it, or keep it and expect to be asked what it's for
- [ ] **`/add` duplicates the add-pin dialog, badly** — **S**
      `app/add/add-pin-form.tsx` only sends `{ title, imageUrl }` — no file
      upload, no description. So the same action produces different results
      depending on which route you used. Either delete the page or make it
      render the same component

## 1.2 Things users will immediately try and fail to do

- [ ] **You cannot delete a pin.** Ever. Not even your own — **S** 🗄️
- [ ] **You cannot edit a pin** — fix a typo in a title, change a description — **S** 🗄️
- [ ] **You cannot delete your own comment** — **S** 🗄️
- [ ] **Author names aren't clickable.** `pin.author` is plain text in
      `pin-card.tsx:49` and `pin/[id]/page.tsx:134`. Authorship is a dead end —
      you see a name and can do nothing with it — **S**
- [ ] **No pagination anywhere.** `/`, `/discover`, `/most-popular` all render
      *every* pin in the database. Fine at 14, unusable at 500 — **M** 🗄️
- [ ] **Comments are a fixed 384px scroll box** with no "load older" — every
      comment ever is in the DOM — **S** 🗄️

## 1.3 Missing states and feedback

- [ ] **No `loading.tsx`, `error.tsx`, or `not-found.tsx` anywhere** — **S**
      A slow page shows nothing; a thrown error shows the raw Next.js overlay;
      a bad URL gets the default 404. Masonry skeletons and a real 404 page are
      an afternoon
- [ ] **The landing page has no empty state.** Every other grid passes an
      `empty` prop; `/` doesn't. With an empty database it renders a blank
      screen — **S**
- [ ] **No layout-shift protection on images.** Cloudinary can produce a tiny
      blurred placeholder; showing it while the full image loads fixes the
      reflow your own Gate 4 calls out — **S**
- [ ] **No upload progress.** A 9MB photo on slow wifi shows a spinner with no
      indication of how far along it is — **S**
- [ ] **No confirmation after acting.** Saving, sharing, and copying give no
      toast. Base UI ships a `toast` primitive you already have installed — **S**

## 1.4 Correctness gaps worth knowing about

- [ ] **Favourites have no `savedAt`.** So `/most-popular`'s "this week" filters
      on when a pin was *posted*, not when it was saved. The page admits this in
      its own footer. One field fixes it — **S** 🗄️
- [ ] **Real-time comments only work on one server.** The SSE emitter is an
      in-process `Map`. Two instances behind a load balancer and users see
      different threads. MongoDB change streams solve it — **M** 🗄️
- [ ] **The download route re-fetches the origin every time** with no caching
      and no rate limit. One person with a loop can burn your bandwidth — **S**
- [ ] **The login dialog loads 20 picsum images** for the background wall.
      Pretty, but it's the heaviest thing on the page and it fires on open — **S**
- [ ] **Search is prefix-matching only.** `lib/recommend/text.ts` tokens, so
      "mountan" finds nothing. No fuzzy matching, no sort options, no result
      count beyond the header — **M**

# Part 2 — Features to build

## 2.1 Surfacing your algorithms

**The highest-value features in this document.** A perfect pHash implementation
is currently invisible in the UI, and examiners grade what they can see. The
plumbing all exists — these are mostly presentation.

### Colour (your k-means output)

- [ ] **Palette strip on the detail page** — **S** 🗄️
      The k dominant colours with their proportions. Instantly proves k-means ran
- [ ] **`/colors` — browse by colour** — **M** 🗄️
      Pick a colour, get results ranked by distance to each stored palette. The
      most demo-able screen in the project
- [ ] **"More in this colour"** on the detail page — **S** 🗄️
- [ ] **Colour swatch chips on `/discover`** — **S** 🗄️
      Sits next to the TF-IDF topic chips already there
- [ ] **Filter any grid by colour family** — warm / cool / monochrome /
      high-contrast, derived from the palette — **M** 🗄️
- [ ] **Sort a board by hue** so a collection reads as a gradient — **S** 🗄️
- [ ] **Auto-generate a theme from a pin's palette** — click a pin, the whole
      UI recolours to its dominant colours — **M**

### Duplicates (your pHash + Hamming output)

- [ ] **Warn at upload time** — **M** 🗄️
      "This looks like a duplicate of X", with a thumbnail, before it's saved
- [ ] **"Near-duplicates" section on the detail page** — **S** 🗄️
- [ ] **`/admin/duplicates` review queue** with the Hamming distance per pair — **M** 🗄️
- [ ] **A live threshold slider on that page** — **S**
      Drag it, watch clusters merge and split. This is *the* Gate 2 demo moment,
      and it's how you'll actually tune the threshold for Phase 5
- [ ] **Render the 64-bit hash as an 8×8 grid** of black/white squares — **S**
      Near-duplicates visibly share a pattern. Makes an abstract number legible
- [ ] **"Find my duplicates"** on the profile — clean up your own board — **S** 🗄️

# Part 4 — What I'd skip

- **PWA / offline** — plausible-sounding, near-zero marks, and it fights the
  Server Component model you've built on
- **Native mobile app** — a whole second project
- **i18n** — real work, invisible to a single-language examiner
- **Live chat / DMs** — enormous scope, unrelated to your algorithms
- **Payments, subscriptions, ads** — nothing to do with the brief
- **CLIP or any ML model** — it would blur the line around your own
  contribution, which is the one thing your tracker warns hardest about

Not features, so they're not in the lists above, but do them before you submit:
**a test suite** (there are currently zero tests, and your pure functions plus
your three algorithms are the easiest things to test), **CI**, and **deploying
to a real URL** so the demo doesn't depend on your laptop.
